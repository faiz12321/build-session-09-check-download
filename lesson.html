How to check a downloaded file against its checksum

Short answer

Some download pages list a SHA-256 checksum, a 64-character fingerprint of the file. If your copy gives the same value, that is strong evidence its content is the same as the file the value was made from. It is not an absolute guarantee, and it is not proof of who made the file or that it is safe. This lesson builds a small read-only Python tool that does the check.

Common mistakes

  1. Thinking a checksum on the download page proves who made the file. A checksum from the same page is useful for catching accidental damage, such as a download that stopped early. If that page were hacked, the file and the checksum could both be swapped, so a match would not show the file is genuine. Where it matters, get the checksum from a source you trust. Ubuntu's documentation, for example, says its images should be verified using a signed list of checksums, even over a secure connection.
  2. Treating a match as proof the file is safe. A checksum matches a harmful file just as happily if the harmful file is the one that was published. Decide separately whether you trust the publisher and where you got the file.
  3. Using an old algorithm. The Python documentation says some algorithms, including MD5 and SHA-1, have known hash collision weaknesses. This lesson uses SHA-256.
  4. Failing a good file over capital letters or spaces. Checksums are often pasted in capitals or with spaces around them. The tool tidies those and refuses anything that is not 64 characters from 0-9 and a-f.
  5. Ignoring a mismatch. A mismatch means a damaged, incomplete or different file. Download it again before you use it.

Frequently asked questions

How do I check a downloaded file against a checksum?

Work out the SHA-256 of your copy and compare it with the value the publisher lists. This lesson builds a small Python tool that does that and reports a match or no match.

Will this change my file?

No. The tool only reads the file. A test checks that one small test file has the same bytes and modified time after a run. That is the only evidence for this claim.

Does a match mean the file is safe?

No. A match is strong evidence that your copy has the same content as the file the checksum was made from. It is not an absolute guarantee. If the publisher or the page was compromised, a matching file can still be harmful.

Is there a Windows tool for this?

Microsoft documents a PowerShell command called Get-FileHash at learn.microsoft.com. This lesson did not run it, so it does not claim the two give the same answer on your PC, only that SHA-256 is a standard.

Why not MD5?

Python's hashlib documentation says some algorithms, including MD5 and SHA-1, have known hash collision weaknesses. This tool only checks SHA-256.
